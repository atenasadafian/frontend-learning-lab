## ۱. HTML چیست؟

**HTML** مخفف `HyperText Markup Language` و به معنای «زبان نشانه‌گذاری ابرمتن» است.

HTML زبان استانداردی برای تعریف ساختار و معنای محتوای صفحات وب است. با استفاده از آن می‌توان عنوان، پاراگراف، تصویر، لینک، جدول، فرم و سایر عناصر یک صفحه را مشخص کرد.

HTML یک زبان برنامه‌نویسی عمومی نیست؛ بلکه یک **زبان نشانه‌گذاری** است. به این معنا که محتوا را با استفاده از عناصر و ویژگی‌ها توصیف می‌کند.

### HTML چه کاربردهایی دارد؟

- ساختاردهی صفحات وب
- نمایش عنوان‌ها، متن‌ها و تصاویر
- ایجاد لینک بین صفحات
- ساخت فرم‌های ثبت‌نام و ورود
- نمایش جدول‌ها و فهرست‌ها
- جاسازی صدا، ویدئو و محتوای خارجی
- تعریف ساختار معنایی صفحات برای مرورگرها، موتورهای جست‌وجو و فناوری‌های کمکی

### تفاوت HTML، CSS و JavaScript

این سه فناوری معمولاً در کنار یکدیگر استفاده می‌شوند.

| فناوری | وظیفه اصلی | مثال |
|---|---|---|
| HTML | ساختار و معنا | عنوان، تصویر، فرم |
| CSS | ظاهر و چیدمان | رنگ، فونت، فاصله |
| JavaScript | رفتار و تعامل | منوی تعاملی، اعتبارسنجی پویا |

برای مثال، در یک دکمه:

- HTML دکمه را ایجاد می‌کند.
- CSS رنگ، اندازه و ظاهر آن را تعیین می‌کند.
- JavaScript می‌تواند هنگام کلیک، عملیات خاصی انجام دهد.

## ۲. تاریخچه HTML

HTML در اوایل دهه ۱۹۹۰ توسط تیم برنرز لی برای اشتراک‌گذاری اسناد در وب معرفی شد.

مراحل مهم توسعه آن عبارت‌اند از:

- **HTML اولیه:** ایجاد ساختارهای ساده برای اسناد و لینک‌ها.
- **HTML 2.0:** استانداردسازی قابلیت‌های اولیه.
- **HTML 4.01:** گسترش امکانات ساختاری و ارتباط بهتر با CSS.
- **XHTML:** نسخه‌ای با قواعد نحوی سخت‌گیرانه‌تر و مبتنی بر XML.
- **HTML5:** گسترش عناصر معنایی، صدا، ویدئو و قابلیت‌های مدرن وب.
- **HTML Living Standard:** استاندارد زنده‌ای که امروزه توسط WHATWG توسعه داده می‌شود.

HTML5 هنوز اصطلاح رایجی برای اشاره به HTML مدرن است، اما مشخصات HTML امروزی به‌صورت پیوسته تکامل پیدا می‌کنند.

## ۳. HTML چگونه کار می‌کند؟

وقتی آدرس یک وب‌سایت را در مرورگر وارد می‌کنیم، معمولاً این مراحل اتفاق می‌افتند:

1. مرورگر درخواست دریافت سند را ارسال می‌کند.
2. سرور فایل HTML را برمی‌گرداند.
3. مرورگر کد HTML را تجزیه می‌کند.
4. ساختار سند به شکل درختی به نام DOM ساخته می‌شود.
5. مرورگر منابعی مانند CSS، تصاویر و JavaScript را دریافت و پردازش می‌کند.
6. صفحه بر اساس ساختار، سبک‌ها و رفتارهای تعریف‌شده نمایش داده می‌شود.

### نمونه HTML

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
    <meta charset="UTF-8">
    <title>اولین صفحه وب</title>
</head>
<body>
    <h1>سلام دنیا!</h1>
    <p>این اولین صفحه HTML من است.</p>
</body>
</html>
```

در این مثال، مرورگر عنوان صفحه را در بخش عنوان پنجره یا تب نمایش می‌دهد و محتوای داخل `body` را در صفحه قرار می‌دهد.

## ۴. پیش‌نیازهای یادگیری

برای شروع یادگیری HTML به دانش برنامه‌نویسی قبلی نیاز ندارید.

ابزارهای موردنیاز:

- یک مرورگر مانند Chrome، Firefox یا Edge
- یک ویرایشگر کد مانند Visual Studio Code
- آشنایی ابتدایی با فایل‌ها و پوشه‌ها

### ساخت اولین فایل

۱. یک پوشه به نام `html-learning` ایجاد کنید.

۲. داخل آن فایلی با نام `index.html` بسازید.

۳. کد نمونه بخش قبل را در فایل قرار دهید.

۴. فایل را ذخیره کنید.

۵. فایل را با مرورگر باز کنید.

برای تجربه توسعه بهتر، می‌توانید از افزونه Live Server در Visual Studio Code استفاده کنید؛ البته برای اجرای ساده HTML، سرور محلی الزامی نیست.

## ۵. ساختار استاندارد یک سند HTML

یک سند HTML استاندارد معمولاً از بخش‌های زیر تشکیل می‌شود:

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">

    <meta name="description" content="آموزش مقدماتی HTML">
    <title>آموزش HTML</title>
</head>
<body>
    <header>
        <h1>به وب‌سایت من خوش آمدید</h1>
    </header>

    <main>
        <p>این محتوای اصلی صفحه است.</p>
    </main>

    <footer>
        <p>تمام حقوق محفوظ است.</p>
    </footer>
</body>
</html>
```

### توضیح بخش‌ها

| عنصر | کاربرد |
|---|---|
| `<!DOCTYPE html>` | معرفی سند به‌عنوان HTML مدرن |
| `<html>` | عنصر ریشه سند |
| `<head>` | اطلاعات و فراداده‌های سند |
| `<meta charset="UTF-8">` | تعیین رمزگذاری کاراکترها |
| `<meta name="viewport">` | تنظیم نمای صفحه برای دستگاه‌های مختلف |
| `<title>` | عنوان سند در تب مرورگر |
| `<body>` | محتوای اصلی قابل نمایش صفحه |
| `<header>` | بخش معرفی یا سربرگ |
| `<main>` | محتوای اصلی صفحه |
| `<footer>` | بخش پایانی صفحه |

### نکته مهم درباره زبان و جهت متن

```html
<html lang="fa" dir="rtl">
```

- `lang="fa"` زبان سند را فارسی معرفی می‌کند.
- `dir="rtl"` جهت کلی متن را راست‌به‌چپ می‌کند.

برای صفحه انگلیسی معمولاً از `lang="en"` و `dir="ltr"` استفاده می‌شود.

## ۶. تگ، عنصر و ویژگی

### ۶.۱. تگ (Tag)

تگ نشانه‌ای است که معمولاً با علامت‌های زاویه‌ای نوشته می‌شود.

```html
<p>سلام دنیا</p>
```

در این مثال:

- `<p>` تگ آغاز است.
- `</p>` تگ پایان است.

### ۶.۲. عنصر (Element)

عنصر شامل تگ آغاز، محتوا و در صورت وجود تگ پایان است.

```html
<p>یادگیری HTML آسان است.</p>
```

کل این ساختار یک عنصر پاراگراف محسوب می‌شود.

### ۶.۳. ویژگی (Attribute)

ویژگی اطلاعات اضافی درباره یک عنصر فراهم می‌کند.

```html
<a href="https://example.com" title="ورود به سایت">
    مشاهده سایت
</a>
```

در این مثال:

- `href` آدرس مقصد را مشخص می‌کند.
- `title` توضیح اضافی ارائه می‌دهد.

مقادیر ویژگی‌ها معمولاً بهتر است داخل کوتیشن قرار بگیرند.

### ۶.۴. عناصر توخالی (Void Elements)

بعضی عناصر محتوای داخلی ندارند و تگ پایان جداگانه نمی‌خواهند.

```html
<img src="photo.jpg" alt="یک منظره">
<br>
<hr>
<input type="text">
<meta charset="UTF-8">
```

از جمله عناصر توخالی مهم:

`area`، `base`، `br`، `col`، `embed`، `hr`، `img`، `input`، `link`، `meta`، `param`، `source`، `track` و `wbr`.

برای نمونه، `img` به شکل `<img>` نوشته می‌شود؛ نوشتن `/` پیش از `>` در HTML الزامی نیست.

### ۶.۵. عناصر تو در تو

عناصر می‌توانند داخل یکدیگر قرار بگیرند، اما باید به ترتیب صحیح بسته شوند.

صحیح:

```html
<p>این یک <strong>متن مهم</strong> است.</p>
```

نادرست:

```html
<p>این یک <strong>متن مهم</p></strong>
```

قانون کلی این است که عناصر تو در تو به ترتیب معکوس باز شدن بسته شوند.

## ۷. تگ‌های متنی

### ۷.۱. عنوان‌ها

HTML شش سطح عنوان دارد.

```html
<h1>عنوان اصلی</h1>
<h2>عنوان سطح دوم</h2>
<h3>عنوان سطح سوم</h3>
<h4>عنوان سطح چهارم</h4>
<h5>عنوان سطح پنجم</h5>
<h6>عنوان سطح ششم</h6>
```

- `h1` معمولاً عنوان اصلی صفحه است.
- `h2` برای بخش‌های اصلی استفاده می‌شود.
- `h3` برای زیربخش‌های `h2` مناسب است.
- سطوح دیگر برای ساختارهای عمیق‌تر به کار می‌روند.

عنوان‌ها را بر اساس ساختار معنایی انتخاب کنید، نه صرفاً اندازه ظاهری.

### ۷.۲. پاراگراف

```html
<p>HTML ساختار محتوای صفحه را تعریف می‌کند.</p>
<p>CSS ظاهر صفحه را کنترل می‌کند.</p>
```

هر پاراگراف معمولاً در خط یا بلوک جداگانه نمایش داده می‌شود.

### ۷.۳. تأکید و اهمیت

```html
<strong>این متن اهمیت زیادی دارد.</strong>

<em>این متن با تأکید خوانده می‌شود.</em>

<b>این متن از نظر ظاهری برجسته است.</b>

<i>این متن با صدای متفاوت یا اصطلاح خاصی مرتبط است.</i>
```

تفاوت مهم:

- `strong` اهمیت معنایی را بیان می‌کند.
- `em` بر تأکید معنایی دلالت دارد.
- `b` و `i` کاربردهای خاص خود را دارند و صرفاً جایگزین عمومی برای تمام نیازهای ظاهری نیستند.

### ۷.۴. خط زیر و خط روی متن

```html
<u>متنی با نشانه‌گذاری خاص</u>

<mark>متن برجسته‌شده</mark>

<del>متن حذف‌شده</del>

<ins>متن اضافه‌شده</ins>

<s>متنی که دیگر دقیق یا مرتبط نیست</s>
```

`u` برای موارد خاص نشانه‌گذاری متن است؛ برای ایجاد خط زیر تزئینی معمولاً CSS مناسب‌تر است.

### ۷.۵. شکستن خط و جداکننده

```html
<p>خط اول<br>خط دوم</p>

<hr>

<p>بخش بعدی متن</p>
```

- `br` شکست خط ایجاد می‌کند.
- `hr` نشان‌دهنده شکست موضوعی بین بخش‌هاست.

از `br` برای ساخت فاصله‌های بزرگ میان بخش‌ها استفاده نکنید؛ فاصله‌گذاری وظیفه CSS است.

### ۷.۶. نقل‌قول و کد

```html
<blockquote>
    طراحی خوب باید استفاده از محتوا را آسان کند.
</blockquote>

<p>دستور <code>git status</code> وضعیت مخزن را نشان می‌دهد.</p>

<pre>
خط اول
    خط دوم با تورفتگی
</pre>

<pre><code>const message = "Hello World";
console.log(message);
</code></pre>
```

- `blockquote` برای نقل‌قول‌های مستقل و طولانی است.
- `q` برای نقل‌قول کوتاه درون متن مناسب است.
- `code` برای نمایش کد به کار می‌رود.
- `pre` فاصله‌ها و شکست خطوط را در محتوای از پیش قالب‌بندی‌شده حفظ می‌کند.

### ۷.۷. زیرنویس و بالانویس

```html
<p>فرمول آب: H<sub>2</sub>O</p>

<p>توان دوم: x<sup>2</sup></p>
```

### ۷.۸. نمایش اختصارات و اطلاعات تماس

```html
<p><abbr title="HyperText Markup Language">HTML</abbr></p>

<address>
    تماس با ما:
    <a href="mailto:info@example.com">info@example.com</a>
</address>
```

`abbr` برای اختصارات و `address` برای اطلاعات تماس مرتبط با نویسنده یا بخش مربوطه کاربرد دارد.

## ۸. لینک‌ها و مسیرها

عنصر `a` برای ایجاد پیوند استفاده می‌شود.

### ۸.۱. لینک خارجی

```html
<a href="https://developer.mozilla.org/">
    مستندات MDN
</a>
```

### ۸.۲. لینک داخلی

```html
<a href="about.html">درباره ما</a>
```

اگر فایل `about.html` در همان پوشه باشد، این مسیر نسبی به آن اشاره می‌کند.

### ۸.۳. لینک به بخشی از صفحه

```html
<a href="#contact">رفتن به بخش تماس</a>

<section id="contact">
    <h2>تماس با ما</h2>
</section>
```

مقدار `id` باید در همان سند یکتا باشد.

### ۸.۴. لینک ایمیل و تلفن

```html
<a href="mailto:info@example.com">ارسال ایمیل</a>

<a href="tel:+982112345678">تماس با ما</a>
```

### ۸.۵. باز کردن لینک در تب جدید

```html
<a
    href="https://example.com"
    target="_blank"
    rel="noopener"
>
    باز کردن سایت
</a>
```

`target="_blank"` معمولاً لینک را در یک تب یا پنجره جدید باز می‌کند. `rel="noopener"` ارتباط صفحه جدید با شیء `window.opener` را محدود می‌کند.

برای لینک‌های خارجی، باز شدن در تب جدید را فقط زمانی انتخاب کنید که واقعاً برای تجربه کاربر مناسب باشد.

### ۸.۶. مسیر مطلق و نسبی

فرض کنید ساختار پروژه چنین است:

```text
project/
├── index.html
├── about.html
├── pages/
│   └── contact.html
└── images/
    └── logo.png
```

نمونه مسیرها:

```html
<a href="about.html">درباره ما</a>

<a href="pages/contact.html">تماس</a>

<img src="images/logo.png" alt="لوگوی سایت">
```

مسیر نسبی بر اساس محل سند فعلی تفسیر می‌شود.

مسیر مطلق وب شامل پروتکل و نام میزبان است:

```html
<a href="https://example.com/about.html">درباره ما</a>
```

## ۹. تصاویر

عنصر `img` برای نمایش تصویر استفاده می‌شود.

```html
<img
    src="images/mountain.jpg"
    alt="کوهی پوشیده از برف در طلوع آفتاب"
    width="800"
    height="500"
>
```

ویژگی‌های مهم:

| ویژگی | کاربرد |
|---|---|
| `src` | مسیر تصویر |
| `alt` | متن جایگزین |
| `width` | عرض مورد انتظار |
| `height` | ارتفاع مورد انتظار |
| `loading="lazy"` | بارگذاری تنبل در شرایط مناسب |
| `srcset` | معرفی نسخه‌های مختلف تصویر |
| `sizes` | اعلام اندازه مورد انتظار تصویر در چیدمان |

### اهمیت `alt`

متن جایگزین به کاربران نابینا و فناوری‌های کمکی کمک می‌کند و در صورت بارگذاری‌نشدن تصویر نیز می‌تواند اطلاعات مفیدی ارائه دهد.

```html
<img src="logo.png" alt="لوگوی شرکت نمونه">
```

برای تصاویر صرفاً تزئینی:

```html
<img src="decoration.png" alt="">
```

قرار دادن `alt=""` به فناوری‌های کمکی اعلام می‌کند که تصویر برای درک محتوا ضروری نیست.

### تصاویر واکنش‌گرا

```html
<img
    src="images/photo-800.jpg"
    srcset="
        images/photo-400.jpg 400w,
        images/photo-800.jpg 800w,
        images/photo-1200.jpg 1200w
    "
    sizes="(max-width: 600px) 100vw, 800px"
    alt="نمایی از طبیعت"
    width="800"
    height="533"
>
```

مرورگر با توجه به شرایط و فضای موردنیاز می‌تواند یکی از منابع تصویر را انتخاب کند.

### بارگذاری تنبل

```html
<img
    src="images/article.jpg"
    alt="تصویر مقاله"
    loading="lazy"
    width="600"
    height="400"
>
```

این روش برای تصاویر پایین صفحه مفید است. برای تصویر اصلی قابل مشاهده در ابتدای صفحه، استفاده از بارگذاری تنبل ممکن است نمایش محتوا را به تأخیر بیندازد.

### عنصر `picture`

```html
<picture>
    <source
        media="(max-width: 600px)"
        srcset="images/mobile.jpg"
    >

    <source
        type="image/webp"
        srcset="images/desktop.webp"
    >

    <img
        src="images/desktop.jpg"
        alt="نمایی از یک شهر"
        width="1200"
        height="800"
    >
</picture>
```

`picture` امکان انتخاب منبع مناسب با توجه به شرایط نمایش یا فرمت پشتیبانی‌شده را فراهم می‌کند.

## ۱۰. لیست‌ها

HTML سه نوع اصلی لیست دارد.

### ۱۰.۱. لیست نامرتب

```html
<ul>
    <li>HTML</li>
    <li>CSS</li>
    <li>JavaScript</li>
</ul>
```

عنصر `ul` برای مواردی مناسب است که ترتیب آن‌ها اهمیت خاصی ندارد.

### ۱۰.۲. لیست مرتب

```html
<ol>
    <li>نصب ویرایشگر</li>
    <li>ایجاد فایل HTML</li>
    <li>اجرای صفحه در مرورگر</li>
</ol>
```

### ۱۰.۳. ویژگی‌های لیست مرتب

```html
<ol start="5">
    <li>مرحله پنجم</li>
    <li>مرحله ششم</li>
</ol>
```

```html
<ol reversed>
    <li>مرحله سوم</li>
    <li>مرحله دوم</li>
    <li>مرحله اول</li>
</ol>
```

### ۱۰.۴. لیست توضیحی

```html
<dl>
    <dt>HTML</dt>
    <dd>زبان نشانه‌گذاری برای ساختار صفحات وب</dd>

    <dt>CSS</dt>
    <dd>زبان استایل‌دهی به صفحات وب</dd>
</dl>
```

- `dl` ظرف لیست توضیحی است.
- `dt` اصطلاح یا عنوان را معرفی می‌کند.
- `dd` توضیح مربوط به آن را ارائه می‌دهد.

## ۱۱. جداول

از جدول برای نمایش داده‌های رابطه‌ای و ساختاریافته استفاده می‌شود، نه برای چیدمان کلی صفحه.

### مثال جدول ساده

```html
<table>
    <caption>برنامه هفتگی کلاس</caption>

    <thead>
        <tr>
            <th scope="col">روز</th>
            <th scope="col">موضوع</th>
            <th scope="col">ساعت</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <td>شنبه</td>
            <td>HTML</td>
            <td>۱۰</td>
        </tr>

        <tr>
            <td>یکشنبه</td>
            <td>CSS</td>
            <td>۱۲</td>
        </tr>
    </tbody>
</table>
```

### عناصر جدول

| عنصر | کاربرد |
|---|---|
| `table` | ظرف جدول |
| `caption` | عنوان جدول |
| `thead` | بخش سرستون‌ها |
| `tbody` | بخش اصلی داده‌ها |
| `tfoot` | بخش پایانی یا جمع‌بندی |
| `tr` | ردیف |
| `th` | سلول عنوان |
| `td` | سلول داده |

### ادغام سلول‌ها

```html
<table>
    <tr>
        <th colspan="2">اطلاعات کاربر</th>
    </tr>
    <tr>
        <td>نام</td>
        <td>علی</td>
    </tr>
</table>
```

ویژگی `colspan` تعداد ستون‌های ادغام‌شده را مشخص می‌کند.

برای ادغام عمودی:

```html
<td rowspan="2">گروه اول</td>
```

از `rowspan` برای پوشش چند ردیف استفاده می‌شود.

## ۱۲. فرم‌ها و ورودی‌ها

فرم‌ها برای دریافت اطلاعات کاربر استفاده می‌شوند.

### ۱۲.۱. فرم پایه

```html
<form action="/register" method="post">
    <label for="username">نام کاربری:</label>

    <input
        type="text"
        id="username"
        name="username"
        required
    >

    <button type="submit">ثبت‌نام</button>
</form>
```

### ویژگی‌های مهم فرم

| ویژگی | کاربرد |
|---|---|
| `action` | مقصد ارسال داده‌ها |
| `method` | روش ارسال درخواست |
| `name` | نام فیلد در داده‌های ارسالی |
| `id` | شناسه یکتای عنصر |
| `required` | الزامی‌کردن فیلد |
| `placeholder` | نمایش راهنمای موقت |
| `autocomplete` | کنترل پیشنهادهای تکمیل خودکار |
| `minlength` | حداقل طول متن |
| `maxlength` | حداکثر طول متن |
| `min` و `max` | محدوده مجاز برای برخی ورودی‌ها |
| `pattern` | الگوی اعتبارسنجی برخی مقادیر متنی |

### ۱۲.۲. انواع ورودی

```html
<input type="text" name="name">
<input type="password" name="password">
<input type="email" name="email">
<input type="number" name="age">
<input type="tel" name="phone">
<input type="url" name="website">
<input type="date" name="birthday">
<input type="time" name="meeting_time">
<input type="search" name="query">
<input type="color" name="color">
<input type="range" name="volume">
<input type="file" name="document">
<input type="hidden" name="source" value="website">
```

نکته: `type="hidden"` برای داده‌هایی است که در رابط معمولی دیده نمی‌شوند، اما به‌خودی‌خود هیچ محرمانگی یا امنیتی ایجاد نمی‌کند.

### ۱۲.۳. برچسب و فیلد

روش توصیه‌شده:

```html
<label for="email">ایمیل:</label>

<input
    type="email"
    id="email"
    name="email"
    autocomplete="email"
    required
>
```

مقدار `for` در `label` باید با `id` فیلد متناظر یکسان باشد.

این کار ارتباط معنایی برچسب و ورودی را مشخص می‌کند و استفاده از فرم را برای فناوری‌های کمکی آسان‌تر می‌سازد.

### ۱۲.۴. رمز عبور

```html
<label for="password">رمز عبور:</label>

<input
    type="password"
    id="password"
    name="password"
    autocomplete="new-password"
    minlength="8"
    required
>
```

ویژگی `type="password"` فقط نمایش کاراکترهای ورودی را پنهان می‌کند. این ویژگی به معنای رمزگذاری یا انتقال امن رمز عبور نیست.

برای فرم ورود موجود، معمولاً `autocomplete="current-password"` مناسب است.

### ۱۲.۵. دکمه‌های رادیویی

```html
<fieldset>
    <legend>روش پرداخت</legend>

    <label>
        <input
            type="radio"
            name="payment"
            value="card"
            required
        >
        کارت بانکی
    </label>

    <label>
        <input
            type="radio"
            name="payment"
            value="cash"
        >
        پرداخت نقدی
    </label>
</fieldset>
```

فیلدهای رادیویی با `name` مشترک، معمولاً یک گروه انتخاب می‌سازند.

### ۱۲.۶. چک‌باکس

```html
<label>
    <input type="checkbox" name="newsletter" value="yes">
    دریافت خبرنامه
</label>
```

چک‌باکس برای انتخاب مستقل یک یا چند گزینه کاربرد دارد.

### ۱۲.۷. فهرست انتخابی

```html
<label for="city">شهر:</label>

<select id="city" name="city" required>
    <option value="">انتخاب کنید</option>
    <option value="tehran">تهران</option>
    <option value="shiraz">شیراز</option>
    <option value="tabriz">تبریز</option>
</select>
```

### ۱۲.۸. فیلد چندخطی

```html
<label for="message">پیام:</label>

<textarea
    id="message"
    name="message"
    rows="5"
    cols="40"
    placeholder="پیام خود را وارد کنید"
></textarea>
```

### ۱۲.۹. انتخاب فایل

```html
<label for="resume">رزومه:</label>

<input
    type="file"
    id="resume"
    name="resume"
    accept=".pdf,.doc,.docx"
>
```

ویژگی `accept` نوع فایل‌های پیشنهادی برای انتخاب را مشخص می‌کند، اما جایگزین اعتبارسنجی سمت سرور نیست.

برای ارسال فایل، معمولاً فرم باید از این ساختار استفاده کند:

```html
<form
    action="/upload"
    method="post"
    enctype="multipart/form-data"
>
    <input type="file" name="file" required>
    <button type="submit">ارسال فایل</button>
</form>
```

### ۱۲.۱۰. دکمه‌ها

```html
<button type="button">عملیات معمولی</button>

<button type="submit">ارسال فرم</button>

<button type="reset">بازنشانی فرم</button>
```

داخل فرم، اگر هدف دکمه ارسال نباشد، بهتر است `type="button"` مشخص شود؛ زیرا دکمه بدون نوع مشخص، در بسیاری از شرایط نقش ارسال فرم را دارد.

### ۱۲.۱۱. اعتبارسنجی اولیه

```html
<form action="/subscribe" method="post">
    <label for="email">ایمیل:</label>

    <input
        type="email"
        id="email"
        name="email"
        required
        maxlength="254"
    >

    <button type="submit">عضویت</button>
</form>
```

مرورگر می‌تواند برخی خطاهای ورودی را قبل از ارسال تشخیص دهد.

**نکته امنیتی:** اعتبارسنجی سمت مرورگر به‌تنهایی کافی نیست. سرور باید داده‌ها را مستقل بررسی کند؛ زیرا کاربر می‌تواند محدودیت‌های سمت کلاینت را دور بزند.

## ۱۳. عناصر معنایی HTML5

عناصر معنایی، نقش و مفهوم بخش‌های مختلف صفحه را مشخص می‌کنند.

```html
<body>
    <header>
        <h1>وب‌سایت آموزشی</h1>

        <nav aria-label="ناوبری اصلی">
            <a href="/">خانه</a>
            <a href="/courses.html">دوره‌ها</a>
        </nav>
    </header>

    <main>
        <section>
            <h2>آخرین دوره‌ها</h2>

            <article>
                <h3>آموزش HTML</h3>
                <p>مقدمه‌ای بر توسعه صفحات وب.</p>
            </article>
        </section>

        <aside>
            <h2>مطالب مرتبط</h2>
            <p>منابع تکمیلی آموزش.</p>
        </aside>
    </main>

    <footer>
        <p>تمام حقوق محفوظ است.</p>
    </footer>
</body>
```

### عناصر معنایی مهم

| عنصر | کاربرد |
|---|---|
| `header` | سربرگ صفحه یا یک بخش |
| `nav` | بخش مهم ناوبری |
| `main` | محتوای اصلی صفحه |
| `section` | بخش موضوعی محتوا |
| `article` | محتوای مستقل و قابل‌تفکیک |
| `aside` | محتوای جانبی مرتبط |
| `footer` | اطلاعات پایانی صفحه یا بخش |
| `figure` | محتوای مستقل مانند تصویر یا نمودار |
| `figcaption` | توضیح محتوای `figure` |
| `time` | نمایش زمان یا تاریخ معنایی |
| `details` | بخش باز و بسته‌شونده |
| `summary` | عنوان قابل انتخاب برای `details` |

### نمونه `figure`

```html
<figure>
    <img
        src="images/chart.png"
        alt="نمودار رشد بازدید وب‌سایت"
        width="600"
        height="350"
    >

    <figcaption>
        تغییر تعداد بازدیدکنندگان در طول ماه
    </figcaption>
</figure>
```

### نمونه `details` و `summary`

```html
<details>
    <summary>HTML چیست؟</summary>
    <p>HTML زبان نشانه‌گذاری برای ساختار صفحات وب است.</p>
</details>
```

این عناصر برای ساخت بخش‌های توضیحی باز و بسته‌شونده، بدون نیاز اولیه به JavaScript، مفید هستند.

## ۱۴. صدا و ویدئو

### ۱۴.۱. ویدئو

```html
<video
    controls
    width="640"
    height="360"
    preload="metadata"
    poster="images/video-cover.jpg"
>
    <source src="videos/lesson.mp4" type="video/mp4">

    مرورگر شما از نمایش این ویدئو پشتیبانی نمی‌کند.
</video>
```

ویژگی‌های مهم:

- `controls`: کنترل‌های پخش را نمایش می‌دهد.
- `poster`: تصویر پیش‌نمایش ویدئو را تعیین می‌کند.
- `preload`: ترجیح اولیه بارگذاری را مشخص می‌کند.
- `autoplay`: تلاش برای پخش خودکار را درخواست می‌کند.
- `loop`: پخش تکراری را فعال می‌کند.
- `muted`: صدای ویدئو را بی‌صدا می‌کند.

پخش خودکار همراه با صدا ممکن است توسط مرورگر مسدود شود.

### ۱۴.۲. صدا

```html
<audio controls preload="metadata">
    <source src="audio/podcast.mp3" type="audio/mpeg">

    مرورگر شما از پخش این فایل صوتی پشتیبانی نمی‌کند.
</audio>
```

### ۱۴.۳. زیرنویس ویدئو

```html
<video controls width="640">
    <source src="videos/course.mp4" type="video/mp4">

    <track
        kind="captions"
        src="captions/fa.vtt"
        srclang="fa"
        label="فارسی"
        default
    >
</video>
```

فایل WebVTT می‌تواند محتوای زیرنویس را نگه‌داری کند. برای ویدئوهای آموزشی، فراهم‌کردن زیرنویس و در صورت نیاز توصیف صوتی به دسترس‌پذیری کمک می‌کند.

## ۱۵. ویژگی‌های عمومی HTML

بسیاری از ویژگی‌ها روی تعداد زیادی از عناصر قابل استفاده‌اند.

### ۱۵.۱. ویژگی `id`

```html
<h2 id="introduction">مقدمه</h2>
```

`id` باید در هر سند یکتا باشد.

کاربردهای آن شامل لینک‌دادن به بخش‌ها، ارتباط عناصر فرم و هدف‌گذاری با CSS و JavaScript است.

### ۱۵.۲. ویژگی `class`

```html
<p class="highlight">متن برجسته</p>
<p class="highlight">متن دیگری با همین کلاس</p>
```

یک کلاس می‌تواند روی چند عنصر قرار بگیرد و یک عنصر نیز می‌تواند چند کلاس داشته باشد.

```html
<div class="card featured">محتوا</div>
```

### ۱۵.۳. ویژگی `style`

```html
<p style="color: blue;">متن آبی</p>
```

این ویژگی استایل درون‌خطی تعیین می‌کند. در پروژه‌های واقعی، معمولاً نگه‌داری CSS در فایل جداگانه بهتر است.

### ۱۵.۴. ویژگی `title`

```html
<abbr title="Cascading Style Sheets">CSS</abbr>
```

`title` می‌تواند اطلاعات تکمیلی فراهم کند، اما نباید تنها راه دسترسی به اطلاعات مهم باشد.

### ۱۵.۵. ویژگی `hidden`

```html
<div hidden>
    این بخش در حالت عادی نمایش داده نمی‌شود.
</div>
```

`hidden` برای محتوایی است که در وضعیت فعلی نباید ارائه شود. برای کنترل‌های تعاملی پیچیده، باید وضعیت ظاهری و دسترس‌پذیری عناصر با دقت مدیریت شود.

### ۱۵.۶. ویژگی `data-*`

```html
<button data-product-id="125">افزودن به سبد خرید</button>
```

ویژگی‌های سفارشی `data-*` برای نگه‌داری داده‌های کوچک مرتبط با یک عنصر در دسترس JavaScript کاربرد دارند.

### ۱۵.۷. ویژگی `contenteditable`

```html
<p contenteditable="true">
    می‌توانید این متن را ویرایش کنید.
</p>
```

این ویژگی امکان ویرایش مستقیم محتوا در مرورگر را فراهم می‌کند، اما ذخیره‌سازی یا ارسال تغییرات را به‌صورت خودکار انجام نمی‌دهد.

### ۱۵.۸. ویژگی `tabindex`

```html
<button tabindex="0">دکمه قابل تمرکز</button>
```

`tabindex` نحوه دریافت تمرکز صفحه‌کلید را تحت تأثیر قرار می‌دهد.

در اغلب موارد، استفاده از عناصر بومی مانند `button` و `a` بهتر از اضافه‌کردن `tabindex` به عناصر غیرتعاملی است. از مقادیر مثبت `tabindex` تا حد امکان اجتناب کنید.

## ۱۶. موجودیت‌های HTML

بعضی کاراکترها در HTML معنای ویژه دارند و باید به شکل موجودیت نمایش داده شوند.

| کاراکتر | موجودیت | کاربرد |
|---|---|---|
| `<` | `&lt;` | کوچک‌تر |
| `>` | `&gt;` | بزرگ‌تر |
| `&` | `&amp;` | علامت و |
| `"` | `&quot;` | کوتیشن دوتایی |
| `'` | `&apos;` | آپاستروف |
| فاصله نشکن | `&nbsp;` | جلوگیری از شکست در آن فاصله |
| © | `&copy;` | علامت کپی‌رایت |
| ® | `&reg;` | علامت ثبت‌شده |

نمونه:

```html
<p>برای نوشتن تگ پاراگراف از &lt;p&gt; استفاده می‌کنیم.</p>

<p>Tom &amp; Jerry</p>

<p>&copy; 2026 Example</p>
```

برای متن فارسی معمولی، اگر فایل با UTF-8 ذخیره شده باشد، معمولاً می‌توانید کاراکترهای فارسی و بسیاری از نمادها را مستقیماً بنویسید.

## ۱۷. کار با CSS و JavaScript

HTML به‌تنهایی برای همه نیازهای طراحی و تعامل کافی نیست.

### ۱۷.۱. اتصال CSS

درون بخش `head`:

```html
<link rel="stylesheet" href="css/style.css">
```

نمونه فایل `css/style.css`:

```css
body {
    font-family: Tahoma, sans-serif;
    background-color: #f5f5f5;
    color: #222;
    line-height: 1.8;
}

h1 {
    color: #1565c0;
}

.container {
    max-width: 1000px;
    margin-inline: auto;
    padding: 20px;
}
```

### ۱۷.۲. اتصال JavaScript

در انتهای `body`:

```html
<script src="js/main.js" defer></script>
```

نمونه فایل `js/main.js`:

```javascript
const button = document.querySelector("#hello-button");

button.addEventListener("click", () => {
    alert("سلام!");
});
```

HTML متناظر:

```html
<button id="hello-button" type="button">
    نمایش پیام
</button>
```

ویژگی `defer` اجرای اسکریپت خارجی را تا زمان پردازش سند به تعویق می‌اندازد و برای اسکریپت‌های معمول صفحه مناسب است.

### ۱۷.۳. تفاوت `div` و `span`

```html
<div class="card">
    <h2>عنوان کارت</h2>
    <p>توضیحات کارت</p>
</div>
```

`div` یک ظرف عمومی بلوکی است.

```html
<p>
    یادگیری <span class="highlight">HTML</span> را شروع کنید.
</p>
```

`span` یک ظرف عمومی درون‌خطی است.

اگر عنصر معنایی مناسب‌تری وجود دارد، معمولاً باید آن را به `div` یا `span` ترجیح داد.

## ۱۸. HTML و سئو

سئو (SEO) به بهینه‌سازی وب‌سایت برای موتورهای جست‌وجو گفته می‌شود. HTML ساختار معنایی و اطلاعات مهم صفحه را در اختیار موتورهای جست‌وجو قرار می‌دهد.

### ۱۸.۱. عنوان صفحه

```html
<title>آموزش HTML از صفر تا پیشرفته | وب‌سایت آموزشی</title>
```

عنوان باید توصیفی، مرتبط با محتوای صفحه و تا حد امکان اختصاصی باشد.

### ۱۸.۲. توضیحات صفحه

```html
<meta
    name="description"
    content="آموزش HTML همراه با مثال‌های عملی، فرم‌ها، جداول و عناصر معنایی."
>
```

توضیحات می‌تواند در برخی نتایج جست‌وجو استفاده شود، اما نمایش آن توسط موتور جست‌وجو تضمین‌شده نیست.

### ۱۸.۳. ساختار صحیح عنوان‌ها

```html
<h1>آموزش HTML</h1>

<section>
    <h2>مبانی HTML</h2>
    <h3>ساختار سند</h3>
</section>

<section>
    <h2>فرم‌ها</h2>
    <h3>انواع ورودی</h3>
</section>
```

عنوان‌ها باید سلسله‌مراتب منطقی داشته باشند.

### ۱۸.۴. متن جایگزین تصاویر

```html
<img
    src="images/html-course.jpg"
    alt="نمونه ساختار یک صفحه HTML"
    width="800"
    height="450"
>
```

متن جایگزین باید محتوای واقعی یا کارکرد تصویر را توصیف کند، نه اینکه با کلمات کلیدی نامرتبط پر شود.

### ۱۸.۵. لینک‌های توصیفی

مناسب:

```html
<a href="/html-guide.html">مطالعه راهنمای HTML</a>
```

کمتر مناسب:

```html
<a href="/html-guide.html">اینجا کلیک کنید</a>
```

متن لینک بهتر است مقصد یا کارکرد آن را به‌روشنی بیان کند.

### ۱۸.۶. آدرس اصلی صفحه

```html
<link
    rel="canonical"
    href="https://example.com/html-guide.html"
>
```

این تگ برای اعلام نسخه اصلی ترجیحی یک صفحه به موتورهای جست‌وجو کاربرد دارد. مقدار آن باید با آدرس واقعی و سیاست محتوایی سایت سازگار باشد.

### ۱۸.۷. داده‌های ساختاریافته

داده‌های ساختاریافته می‌توانند به موتورهای جست‌وجو در درک محتوای صفحه کمک کنند. قالب JSON-LD یکی از روش‌های رایج است.

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "آموزش HTML",
  "description": "راهنمای مقدماتی HTML",
  "inLanguage": "fa"
}
</script>
```

اطلاعات واقعی، مانند نویسنده و تاریخ انتشار، باید فقط در صورت صحت به داده‌های ساختاریافته اضافه شوند. وجود این داده‌ها به‌تنهایی تضمین‌کننده نمایش نتیجه ویژه در موتور جست‌وجو نیست.

## ۱۹. دسترس‌پذیری

دسترس‌پذیری وب (Web Accessibility) یعنی طراحی سایت به شکلی که افراد با توانایی‌ها و ابزارهای مختلف بتوانند از آن استفاده کنند.

### اصول مهم

- استفاده از عناصر معنایی HTML
- ارائه متن جایگزین مناسب برای تصاویر
- ارتباط صحیح `label` و فیلدهای فرم
- امکان استفاده از صفحه‌کلید
- ایجاد عنوان‌های توصیفی
- نمایش واضح تمرکز صفحه‌کلید
- استفاده نکردن از رنگ به‌عنوان تنها وسیله انتقال معنا
- ارائه زیرنویس برای محتوای صوتی و تصویری در موارد لازم
- حفظ کنتراست کافی متن و پس‌زمینه

### نمونه فرم دسترس‌پذیر

```html
<form action="/contact" method="post">
    <div>
        <label for="full-name">نام کامل</label>

        <input
            type="text"
            id="full-name"
            name="full_name"
            autocomplete="name"
            required
        >
    </div>

    <div>
        <label for="contact-email">ایمیل</label>

        <input
            type="email"
            id="contact-email"
            name="email"
            autocomplete="email"
            required
        >
    </div>

    <div>
        <label for="contact-message">پیام</label>

        <textarea
            id="contact-message"
            name="message"
            rows="5"
            required
        ></textarea>
    </div>

    <button type="submit">ارسال پیام</button>
</form>
```

### نقش ARIA

ARIA مجموعه‌ای از ویژگی‌ها برای بهبود معنای دسترس‌پذیر رابط‌های وب است.

نمونه:

```html
<nav aria-label="ناوبری اصلی">
    <a href="/">خانه</a>
    <a href="/about.html">درباره ما</a>
</nav>
```

ARIA باید برای مواردی استفاده شود که معنای موردنیاز با HTML بومی به‌خوبی بیان نمی‌شود. استفاده نادرست از ARIA ممکن است دسترس‌پذیری را بدتر کند.

**قاعده کاربردی:** در صورت امکان، ابتدا از عنصر بومی HTML استفاده کنید.

## ۲۰. HTML و امنیت

HTML ساختار صفحه را تعریف می‌کند، اما به‌تنهایی امنیت یک برنامه وب را تضمین نمی‌کند.

### ۲۰.۱. اعتبارسنجی داده‌ها

```html
<input type="email" name="email" required>
```

این ویژگی‌ها به بررسی اولیه ورودی کمک می‌کنند، اما اعتبارسنجی سمت سرور همچنان ضروری است.

### ۲۰.۲. جلوگیری از تزریق HTML

اگر داده‌ای از کاربر دریافت می‌کنید و آن را در صفحه نمایش می‌دهید، نباید بدون بررسی و پاک‌سازی مناسب به‌عنوان HTML اجرا شود.

برای مثال، اگر کاربر رشته‌ای شامل تگ `<script>` وارد کند، برنامه نباید آن را به‌صورت ناامن به محتوای اجرایی صفحه تبدیل کند.

برای نمایش متن ساده در JavaScript، استفاده از `textContent` معمولاً از قرار دادن مستقیم ورودی کاربر در `innerHTML` امن‌تر است.

### ۲۰.۳. لینک‌های خارجی

```html
<a
    href="https://example.com"
    target="_blank"
    rel="noopener noreferrer"
>
    باز کردن سایت خارجی
</a>
```

`noopener` دسترسی صفحه جدید به `window.opener` را محدود می‌کند و `noreferrer` نیز اطلاعات ارجاع‌دهنده را ارسال نمی‌کند. استفاده از `noreferrer` باید با نیازهای واقعی پروژه سازگار باشد.

### ۲۰.۴. داده‌های محرمانه

اطلاعاتی مانند رمز عبور، کلید API یا توکن محرمانه را در HTML سمت کاربر قرار ندهید. کد و داده‌های ارسال‌شده به مرورگر برای کاربران قابل مشاهده‌اند.

## ۲۱. ساختار پوشه‌های پروژه

برای یک پروژه ساده HTML، می‌توانید از ساختار زیر استفاده کنید:

```text
my-website/
├── index.html
├── about.html
├── contact.html
├── css/
│   └── style.css
├── js/
│   └── main.js
├── images/
│   ├── logo.png
│   └── banner.jpg
└── README.md
```

### مسئولیت فایل‌ها

- `index.html`: صفحه اصلی
- `about.html`: صفحه درباره ما
- `contact.html`: صفحه تماس
- `css/style.css`: استایل‌های سایت
- `js/main.js`: منطق تعاملی
- `images/`: تصاویر پروژه
- `README.md`: مستندات پروژه

### اتصال فایل‌ها

در `index.html`:

```html
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>وب‌سایت من</title>

    <link rel="stylesheet" href="css/style.css">
    <script src="js/main.js" defer></script>
</head>
```

برای یک پروژه ساده، همین ساختار کافی است. در پروژه‌های بزرگ‌تر می‌توانید پوشه‌هایی برای فونت‌ها، فایل‌های رسانه‌ای و بخش‌های مختلف برنامه ایجاد کنید.

## ۲۲. تگ‌های منسوخ و اشتباهات رایج

### ۲۲.۱. تگ‌های قدیمی

در HTML مدرن بهتر است از عناصر و روش‌های مناسب امروزی استفاده شود.

| روش قدیمی | جایگزین یا روش مناسب |
|---|---|
| `<font>` | CSS برای تعیین فونت و رنگ |
| `<center>` | CSS برای تراز و چیدمان |
| `<big>` | CSS برای اندازه متن |
| `<strike>` | CSS یا `del` و `s` بر اساس معنا |
| `<tt>` | `code` یا CSS متناسب با کاربرد |
| `bgcolor` | CSS برای رنگ پس‌زمینه |

برخی از این عناصر قدیمی منسوخ شده‌اند و نباید در پروژه‌های جدید به آن‌ها تکیه کرد.

### ۲۲.۲. استفاده از تگ اشتباه

نادرست از نظر معنا:

```html
<h1>متن اصلی</h1>
<h1>عنوان بخش فرعی</h1>
```

این ساختار لزوماً از نظر نحوی نامعتبر نیست، اما اگر عنوان دوم زیربخش عنوان اول باشد، معمولاً `h2` انتخاب مناسب‌تری است.

### ۲۲.۳. فراموش‌کردن `alt`

```html
<img src="product.jpg">
```

برای تصویری معنادار بهتر است متن جایگزین تعریف شود:

```html
<img src="product.jpg" alt="کفش ورزشی مشکی">
```

### ۲۲.۴. استفاده از `div` برای همه‌چیز

```html
<div>عنوان</div>
<div>محتوای اصلی</div>
<div>منوی سایت</div>
```

اگر هدف عنصر مشخص است، استفاده از عناصر معنایی مانند `h1`، `main` و `nav` ساختار روشن‌تری ایجاد می‌کند.

### ۲۲.۵. استفاده نادرست از `placeholder`

```html
<input type="email" placeholder="ایمیل خود را وارد کنید">
```

`placeholder` جایگزین مناسبی برای `label` نیست؛ زیرا ممکن است پس از تایپ کاربر ناپدید شود و همیشه برای توضیح دائمی فیلد مناسب نیست.

### ۲۲.۶. استفاده از مسیر اشتباه

```html
<img src="/images/photo.jpg" alt="تصویر">
```

مسیر آغازشده با `/` معمولاً از ریشه وب‌سایت محاسبه می‌شود. اگر پروژه در زیرمسیر یک وب‌سایت منتشر شده باشد، این مسیر ممکن است با محل واقعی فایل سازگار نباشد.

### ۲۲.۷. اشتباه در نام فایل

در بسیاری از محیط‌های میزبانی، حروف بزرگ و کوچک نام فایل‌ها متفاوت محسوب می‌شوند.

اگر فایل `Logo.png` نام دارد، نباید بدون توجه به محیط اجرا آن را با مسیر `logo.png` فراخوانی کنید.

## ۲۳. نکات حرفه‌ای و بهترین روش‌ها

### ۲۳.۱. استفاده از DOCTYPE

هر سند HTML معمولی را با این اعلان شروع کنید:

```html
<!DOCTYPE html>
```

### ۲۳.۲. تعیین رمزگذاری و viewport

```html
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

این موارد به تفسیر صحیح کاراکترها و نمایش مناسب صفحه در دستگاه‌های مختلف کمک می‌کنند.

### ۲۳.۳. ساختار معنایی مناسب

- از `main` برای محتوای اصلی استفاده کنید.
- از `nav` برای ناوبری اصلی یا بخش‌های مهم ناوبری بهره ببرید.
- عنوان‌ها را بر اساس سلسله‌مراتب محتوا تنظیم کنید.
- برای محتواهای مستقل از `article` استفاده کنید.
- تنها به دلیل ظاهر، عنصر معنایی نامناسب انتخاب نکنید.

### ۲۳.۴. جداکردن HTML، CSS و JavaScript

در پروژه‌های معمول، تفکیک ساختار، ظاهر و رفتار باعث خوانایی و نگه‌داری بهتر کد می‌شود.

### ۲۳.۵. استفاده از HTML معتبر

کد را با ابزار اعتبارسنجی بررسی کنید تا خطاهای نحوی، ویژگی‌های نامعتبر و برخی مشکلات ساختاری شناسایی شوند.

### ۲۳.۶. توجه به واکنش‌گرایی

HTML باید با CSS واکنش‌گرا همراه شود تا محتوا در موبایل، تبلت و دسکتاپ مناسب نمایش داده شود.

### ۲۳.۷. تعیین اندازه تصاویر

برای بسیاری از تصاویر، تعیین `width` و `height` به مرورگر کمک می‌کند فضای مناسب را از قبل در نظر بگیرد و از جابه‌جایی ناخواسته محتوا جلوگیری شود.

### ۲۳.۸. انتخاب نوع ورودی مناسب

برای مثال:

- ایمیل: `type="email"`
- رمز عبور: `type="password"`
- تاریخ: `type="date"`
- جست‌وجو: `type="search"`

نوع مناسب ورودی تجربه کاربری را بهتر می‌کند و در برخی دستگاه‌ها صفحه‌کلید متناسبی ارائه می‌دهد.

### ۲۳.۹. بررسی صفحه‌کلید

اطمینان حاصل کنید که لینک‌ها، دکمه‌ها و فرم‌ها با صفحه‌کلید قابل استفاده باشند.

### ۲۳.۱۰. آزمایش در مرورگرها

صفحه را در چند مرورگر و اندازه صفحه بررسی کنید؛ رفتار همه قابلیت‌ها لزوماً در همه محیط‌ها کاملاً یکسان نیست.

## ۲۴. پروژه عملی

در این بخش یک صفحه معرفی شخصی ساده با HTML می‌سازیم.

### هدف پروژه

ایجاد صفحه‌ای شامل:

- سربرگ و منوی ناوبری
- معرفی شخص
- مهارت‌ها
- پروژه‌ها
- فرم تماس
- بخش پایانی

### کد کامل `index.html`

```html
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">

    <meta
        name="description"
        content="صفحه معرفی شخصی و نمونه‌کارهای من"
    >

    <title>صفحه شخصی من</title>
</head>
<body>

    <header>
        <h1>وب‌سایت شخصی من</h1>

        <nav aria-label="ناوبری اصلی">
            <a href="#about">درباره من</a>
            <a href="#skills">مهارت‌ها</a>
            <a href="#projects">پروژه‌ها</a>
            <a href="#contact">تماس</a>
        </nav>
    </header>

    <main>
        <section id="about">
            <h2>درباره من</h2>

            <p>
                سلام! من یک توسعه‌دهنده وب در حال یادگیری هستم.
                هدف من ساخت صفحات وب کاربردی و دسترس‌پذیر است.
            </p>

            <img
```

## جمع‌بندی

HTML پایه ساختار صفحات وب است. برای یادگیری مؤثر آن، لازم است علاوه بر شناخت تگ‌ها، نحوه استفاده صحیح از عناصر معنایی، فرم‌ها، تصاویر، لینک‌ها و ویژگی‌ها را نیز تمرین کنید.

نکات کلیدی:

1. HTML زبان نشانه‌گذاری است، نه زبان برنامه‌نویسی عمومی.
2. از ساختار استاندارد سند و عناصر معنایی استفاده کنید.
3. برای ظاهر صفحه از CSS و برای تعامل از JavaScript کمک بگیرید.
4. دسترس‌پذیری و سئو را از ابتدای طراحی در نظر بگیرید.
5. اعتبارسنجی مرورگر جایگزین اعتبارسنجی سمت سرور نیست.
6. با ساخت پروژه‌های کوچک و بررسی مستندات رسمی، دانش خود را تقویت کنید.

**پیشنهاد نهایی:** پس از یادگیری مبانی HTML، یک صفحه شخصی بسازید، آن را با CSS طراحی کنید و سپس با JavaScript قابلیت‌های تعاملی به آن اضافه کنید.

## مفاهیم و مباحث کلیدی

در این بخش، تمرین‌ها و نمونه‌کارهای مرتبط با موارد زیر قرار می‌گیرد:

1.**مبانی و تگ‌های پایه:**
   - آشنایی با ساختار استاندارد یک سند HTML (`<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`)
   - تگ‌های متنی (سرتیترها از `<h1>` تا `<h6>`، پاراگراف‌ها، نقل‌قول‌ها و متن‌های تاکیدی)
   - لینک‌ها (`<a>`) و تصاویر (`<img>`)

2.**لیست‌ها و جداول:**
   - لیست‌های مرتب (`<ol>`) و نامرتب (`<ul>`)
   - ساخت جدول‌های اطلاعاتی ساختاریافته (`<table>`, `<tr>`, `<th>`, `<td>`)

3.**فرم‌های تعاملی:**
   - دریافت اطلاعات از کاربر با انواع `input`ها (متن، ایمیل، پسورد، تاریخ و...)
   - المان‌های انتخاب مانند `select`، `textarea` و دکمه‌های ارسال (`button`)
   - برچسب‌گذاری صحیح (`<label>`) برای بهبود تجربه کاربری و دسترسی‌پذیری

4.**استانداردهای معنایی (Semantic HTML):**
   - استفاده از تگ‌های مفهومی مدرن مانند `<header>`، `<nav>`، `<main>`، `<section>`، `<article>`، `<aside>` و `<footer>` برای بهبود ساختار سئو (SEO) و خوانایی کد.
